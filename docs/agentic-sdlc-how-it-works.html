Agentic SDLC
for TaskLite

An 8-step, Claude-driven software delivery pipeline — from user story to pull request. Every step is AI-assisted with a dedicated agent, skill, and slash command. Story Type classification adapts the pipeline to API, UI, Full-Stack, or Developer Tooling work. Every commit, push, and PR requires explicit human approval.

The pipeline

8-Step SDLC Workflow

Each step is triggered by a slash command. Claude reads the previous step's output, applies its agent persona and skill instructions, and produces the next document or set of files. Human approval gates prevent progress until a human explicitly signs off.

At Step 1.5, classifies the story as API, UI, Full-Stack, or Developer Tooling — this single field gates which checklists, test frameworks, and review areas activate downstream.

Architecture

Building Blocks

Five types of components work together. Commands orchestrate agents; agents load skills and prompts; hooks enforce quality at Git lifecycle events. Story Type flows through every layer — each component reads it and activates or skips the appropriate sections.

🤖

Agents · 7 total

Specialised Claude subagents with defined personas, step-by-step processes, and strict operating rules. Each agent reads the Story Type from requirements.md and activates the appropriate checklists — UI-specific areas are skipped entirely for API and Developer Tooling stories.

requirements-analyst architect design-reviewer implementation-planner code-reviewer test-engineer documentation-reviewer
📚

Skills · 6 total

Reusable instruction sets Claude loads before a specific type of work. Skills adapt to Story Type: frontend sections (Area 11 code review, Vitest/RTL/Playwright testing, Section 8a security, WCAG NFRs) activate only when Story Type is UI or Full-Stack.

requirements-analysis architecture-design code-review testing documentation-sync security-review
⚡

Commands · 8 total

Slash commands that orchestrate each pipeline step. Each command specifies which agent and skill to load, which documents to read, what to produce, and exactly when to pause for human approval.

/requirements /architecture /design-review /plan /implement /review /verify /prepare-pr
💬

Prompts · 5 total

System-level prompts that establish each agent's persona, core principles, output rules, and "what to do when uncertain" guidance. Loaded automatically when the corresponding command is invoked.

requirements-prompt architecture-prompt review-prompt verification-prompt documentation-prompt
🔗

Hooks · 3 total

Shell scripts that fire at Git lifecycle events. They enforce quality gates automatically — no manual step required. A failing hook blocks the commit or push until the underlying issue is resolved.

pre-commit.sh — lint · type-check · secrets post-edit.sh — auto-lint · doc-validate pre-push.sh — full tests · quality checks
📄

SDLC Artifacts · 6 core

The documents each step produces and the next step consumes. Once approved by the human, each artifact becomes the authoritative source of truth for everything downstream. requirements.md is the most critical — its Story Type field controls the entire pipeline's behaviour.

Non-negotiable

How Claude Operates

These rules are enforced across every agent and every session. They are defined in CLAUDE.md and applied regardless of which command is running.

🚫

Never invent

No invented endpoints, credentials, SLA targets, or owner names. Unknown values are always marked "Not Identified" with a reason — never guessed.

🔐

Human approval gates

Every git commit, push, and PR creation requires explicit human approval. Claude stages the diff and waits — it never auto-commits.

🔒

No secrets in output

Passwords, tokens, API keys, and connection strings never appear in generated docs, PR descriptions, or logs. scan-secrets.sh runs on every push.

📊

Honest reporting

Tests and checks are never claimed as passing if they were not run. Every unexecuted check is listed explicitly under "Not Executed."

❓

Ask before assuming

Ambiguous requirements trigger a numbered list of clarification questions. Claude presents all questions at once and waits for answers before drafting anything.

⚠️

Surface conflicts

When source files or documents disagree, the conflict is surfaced to the human with both sides shown. Claude never silently picks one value over another.

🏗️

Preserve architecture

The approved architecture.md is not modified during implementation without a human-reviewed design change. Scope creep is caught and surfaced, not absorbed silently.

📋

One task at a time

During /implement, Claude works on exactly one TASK from impl-plan.md at a time, runs tests after each, and updates the task status before moving to the next.

🎛️

Conditional activation

Agents read Story Type from requirements.md before running any checklist. UI-specific areas (Area 11, Vitest/Playwright, WCAG NFRs, Section 8a security) activate only for UI and Full-Stack stories — never for API-only or Developer Tooling work.
